### Пошаговые руководства (6 документов)

#### **Шаг 1: Batch Submission** (`phase3_step1_submission.md`)

- **Цель:** Отправка pending пакетов в Google Batch API
- **Время:** 2-3 часа
- **Ключевые темы:**
  - Структура `inline_requests` (JSON Lines формат)
  - Получение `google_batch_id` от API
  - Обновление статуса в БД
  - Тестирование с моками и реальным API
- **Соотношение:** ~80% объяснений, 20% кода

---

#### **Шаг 2: Batch Polling** (`phase3_step2_polling.md`)

- **Цель:** Отслеживание статусов активных пакетов
- **Время:** 1-2 часа
- **Ключевые темы:**
  - 5 статусов Google Batch API (STATE_UNSPECIFIED → STATE_COMPLETED)
  - Маппинг статусов (Google → наша БД)
  - Оптимизация через `batches.list()`
  - Рекомендации по частоте polling (10-300 сек)
- **Особенность:** Бесплатное тестирование (чтение статусов)

---

#### **Шаг 3: Batch Retrieval** (`phase3_step3_retrieval.md`)

- **Цель:** Скачивание и обработка результатов
- **Время:** 2-3 часа
- **Ключевые темы:**
  - Структура JSONL результатов (JSON Lines)
  - Извлечение base64 изображений из `inline_data`
  - Сопоставление результатов с задачами через `custom_id`
  - Обработка ошибок (успех vs провал)
  - Использование `target_path` из задачи
- **Сложность:** Высокая (работа с HTTP, декодирование, файловая система)

---

#### **Шаг 4: TTS Queue Integration** (`phase3_step4_tts_queue.md`)

- **Цель:** Интеграция реального TTS вместо моков
- **Время:** 2-3 часа
- **Ключевые темы:**
  - Синхронный синтез речи через Gemini TTS API
  - Декодирование WAV из base64
  - Rate limiting (1.8 сек между запросами = 20/мин)
  - Валидация голосов (Aoede, Charon, Fenrir, Kore, Puck)
  - Обработка ошибок (невалидный голос, длинный текст)
- **Стоимость тестирования:** ~$0.01-0.05

---

#### **Шаг 5: MCP Tools Integration** (`phase3_step5_mcp_tools.md`)

- **Цель:** Создание 4 инструментов для AI-агента
- **Время:** 3-4 часа
- **Инструменты:**
  1. `batch_generate_images()` — создание batch задач
  2. `queue_generate_audio()` — создание TTS задач
  3. `check_task_status()` — проверка статуса задачи
  4. `check_batch_progress()` — проверка прогресса пакета
- **Интеграция:** Все инструменты регистрируются через FastMCP в `server.py`
- **Стоимость тестирования:** $0.00 (только создание задач)

---

#### **Шаг 6: E2E Testing** (`phase3_step6_testing.md`)

- **Цель:** Комплексное тестирование всей системы
- **Время:** 2-3 часа
- **Тестовые сценарии:**
  - E2E Batch Images (5 изображений, полный цикл)
  - E2E TTS Queue (3 задачи с rate limiting)
  - Cost Verification (подтверждение экономии 50%)
  - Error Handling (невалидные данные)
- **Метрики производительности:**
  - Batch Throughput: > 10 images/min
  - TTS Latency: < 10 sec/task
- **Стоимость тестирования:** ~$0.05-0.10
