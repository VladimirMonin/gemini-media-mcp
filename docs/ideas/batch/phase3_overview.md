## Цель Фазы 3

Превратить **моки** в **реальные интеграции** с Google Batch API и TTS. После завершения система сможет:

1. **Отправлять задачи в Google Batch API** (50% скидка на изображения)
2. **Отслеживать статус выполнения** через polling
3. **Получать результаты** и сохранять их на диск
4. **Обрабатывать TTS последовательно** через local_queue с rate limiting

## Структура документации Фазы 3

Фаза разбита на **6 логических шагов**, каждый в отдельном документе:

### 📘 Шаг 1: Batch Submission (Отправка пакетов)

**Файл:** `phase3_step1_submission.md`  
**Время:** 2-3 часа  
**Цель:** Научиться отправлять pending задачи в Google Batch API

**Что делаем:**

- Формируем `inline_requests` из задач БД
- Вызываем `client.batches.create()`
- Обновляем статусы batch → SUBMITTED, tasks → SUBMITTED
- Сохраняем `google_batch_id` для дальнейшего tracking

---

### 📗 Шаг 2: Batch Polling (Отслеживание статуса)

**Файл:** `phase3_step2_polling.md`  
**Время:** 1-2 часа  
**Цель:** Научиться проверять статус SUBMITTED пакетов

**Что делаем:**

- Получаем список SUBMITTED/PROCESSING пакетов из БД
- Для каждого вызываем `client.batches.get(google_batch_id)`
- Маппим статусы Google → наши статусы в БД
- Обновляем статусы пакетов при изменениях

---

### 📙 Шаг 3: Batch Retrieval (Получение результатов)

**Файл:** `phase3_step3_retrieval.md`  
**Время:** 2-3 часа  
**Цель:** Научиться скачивать результаты COMPLETED пакетов

**Что делаем:**

- Находим COMPLETED пакеты в БД
- Скачиваем JSONL файл из `output_file_uri`
- Парсим результаты (сопоставляем по `custom_id`)
- Сохраняем изображения из base64 на диск
- Обновляем статусы задач → COMPLETED/FAILED

---

### 📕 Шаг 4: TTS Queue Integration (Последовательная обработка аудио)

**Файл:** `phase3_step4_tts_queue.md`  
**Время:** 2-3 часа  
**Цель:** Интегрировать реальный TTS вместо моков

**Что делаем:**

- Заменяем `time.sleep(2)` на `generate_audio_from_yaml()`
- Добавляем обработку ошибок TTS API
- Сохраняем результат в `target_path`
- Оставляем rate limiting (10 секунд между задачами)

---

### 📔 Шаг 5: MCP Async Tools (Инструменты для агента)

**Файл:** `phase3_step5_mcp_tools.md`  
**Время:** 3-4 часа  
**Цель:** Создать MCP tools для постановки задач в очередь

**Что делаем:**

- `create_image_batch()` — создать пакет на генерацию N изображений
- `check_batch_status()` — проверить прогресс выполнения пакета
- `check_task_status()` — проверить статус одной задачи
- `create_audio_queue()` — поставить TTS задачу в очередь
- `cancel_batch()` — отменить pending пакет

---

### 📓 Шаг 6: E2E Testing & Cleanup (Финальная проверка)

**Файл:** `phase3_step6_testing.md`  
**Время:** 2-3 часа (опционально)  
**Цель:** Написать E2E тесты и навести порядок

**Что делаем:**

- E2E тест генерации изображений (реальный Batch API)
- E2E тест TTS генерации (реальный TTS API)
- Feature flag `RUN_E2E_TESTS=1` для контроля стоимости
- Cleanup: удалить `manager_old.py`, обновить `README.md`
- Добавить seed data для `TTS_QUEUE` operation_type
